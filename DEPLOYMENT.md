# SyncFlow Protocol - Production Deployment Guide

This guide will walk you through deploying SyncFlow Protocol to production using Render (backend) and Vercel (frontend).

## Architecture Overview

- **Frontend**: Next.js 14 deployed on Vercel
- **Backend**: Express.js API deployed on Render
- **Database**: PostgreSQL (managed by Render or Neon)

---

## Prerequisites

1. GitHub account with your repository pushed
2. [Render account](https://render.com) (free tier available)
3. [Vercel account](https://vercel.com) (free tier available)
4. API keys:
   - Crypto.com Dashboard API Key
   - Google Gemini API Key (free tier)
   - Database URL (PostgreSQL)

---

## Part 1: Deploy Backend to Render

### Step 1: Create Render Account
1. Go to [render.com](https://render.com)
2. Sign up with GitHub
3. Authorize Render to access your repository

### Step 2: Deploy Using render.yaml
1. In Render dashboard, click **"New +"** → **"Blueprint"**
2. Connect your GitHub repository: `SyncFlow-Protocol-x402`
3. Render will automatically detect `render.yaml`
4. Click **"Apply Blueprint"**

### Step 3: Configure Environment Variables
Render will create two services:
- **syncflow-backend** (Web Service)
- **syncflow-db** (PostgreSQL Database)

For the **syncflow-backend** service, add these environment variables:

```bash
# Required - Database
DATABASE_URL=<automatically-populated-by-render-db>

# Required - Security
JWT_SECRET=<auto-generated-by-render>
FRONTEND_URL=https://your-app.vercel.app

# Required - Blockchain
CDC_DASHBOARD_API_KEY=<your-cdc-api-key>
CRONOS_RPC_URL=https://evm-t3.cronos.org
CRONOS_CHAIN_ID=338

# Required - AI Provider (choose at least one)
GEMINI_API_KEY=<your-gemini-api-key>
# OR
ANTHROPIC_API_KEY=<your-anthropic-api-key>
# OR
OPENAI_API_KEY=<your-openai-api-key>

# Optional - Autonomous Execution
PRIVATE_KEY=<testnet-private-key-for-agent>
X402_NETWORK=cronos-testnet
X402_RECEIVER_ADDRESS=<receiver-wallet-address>
```

### Step 4: Get Backend URL
After deployment completes:
1. Your backend will be live at: `https://syncflow-backend.onrender.com`
2. Test the health endpoint: `https://syncflow-backend.onrender.com/health`
3. **Copy this URL** - you'll need it for frontend deployment

## Part 2: Deploy Frontend to Vercel

### Step 1: Connect to Vercel
1. Go to [vercel.com](https://vercel.com)
2. Sign up with GitHub
3. Click **"Add New Project"**
4. Import your repository: `SyncFlow-Protocol-x402`

### Step 2: Configure Build Settings
Vercel will auto-detect Next.js. Verify these settings:

```
Framework Preset: Next.js
Root Directory: packages/frontend
Build Command: npm run build
Output Directory: .next
Install Command: npm install
```

### Step 3: Configure Environment Variables
In Vercel project settings → **Environment Variables**, add:

```bash
# Backend API (CRITICAL - use your Render URL)
BACKEND_URL=https://syncflow-backend.onrender.com

# Database (same as backend)
DATABASE_URL=<same-postgresql-url-from-render>

# JWT Secret (must match backend)
JWT_SECRET=<same-jwt-secret-from-backend>

# Public Variables (exposed to browser)
NEXT_PUBLIC_API_URL=http://localhost:3001
NEXT_PUBLIC_CRONOS_CHAIN_ID=338
NEXT_PUBLIC_CRONOS_RPC_URL=https://evm-t3.cronos.org
NEXT_PUBLIC_CRONOS_EXPLORER=https://cronos.org/explorer
```

### Step 4: Deploy
1. Click **"Deploy"**
2. Wait for build to complete (~3-5 minutes)
3. Your frontend will be live at: `https://your-app.vercel.app`

### Step 5: Update Backend CORS
1. Go back to Render dashboard
2. Open **syncflow-backend** → **Environment**
3. Update `FRONTEND_URL` to your actual Vercel URL:
   ```
   FRONTEND_URL=https://your-app.vercel.app
   ```
4. Click **"Save Changes"** (this will trigger a redeploy)

## Part 3: Database Setup

### Option A: Use Render's PostgreSQL (Recommended)
Render automatically creates and connects the database when using `render.yaml`. No additional setup needed!

### Option B: Use Neon Database (Alternative)
If you prefer Neon (what you're currently using locally):

1. Go to [neon.tech](https://neon.tech)
2. Create a project
3. Copy the connection string
4. Add to both Render and Vercel:
   ```
   DATABASE_URL=postgresql://user:password@host/db?sslmode=require
   ```

## Common Issues

### Issue: "Failed to fetch" in frontend chat
**Solution**: Check that:
1. `BACKEND_URL` in Vercel matches your Render URL
2. `FRONTEND_URL` in Render includes your Vercel domain
3. Both are using `https://` (not `http://`)

### Issue: CORS errors
**Solution**:
1. Verify `FRONTEND_URL` in Render backend
2. Check that it matches your Vercel deployment URL exactly
3. Redeploy backend after changing CORS settings

### Issue: Database connection errors
**Solution**:
1. Ensure `DATABASE_URL` is identical in both Render and Vercel
2. Check that connection string includes `?sslmode=require`
3. Verify database is running in Render dashboard

### Issue: "Lite Mode" in chat (no AI responses)
**Solution**:
1. Verify `GEMINI_API_KEY` (or other AI key) is set in Render
2. Check backend logs in Render dashboard for AI initialization
3. Restart backend service after adding API key

### Issue: Build fails on Vercel
**Solution**:
1. Check that `DATABASE_URL` is set (required for Prisma)
2. Verify all `NEXT_PUBLIC_*` variables are present
3. Check build logs for specific error messages

## Security Checklist

Before going live:

- [ ] All `.env` files are in `.gitignore`
- [ ] `JWT_SECRET` is strong and unique (auto-generated by Render)
- [ ] `PRIVATE_KEY` is stored securely (use testnet key only)
- [ ] CORS is restricted to your Vercel domain only
- [ ] Rate limiting is enabled (already configured in code)
- [ ] Database uses SSL connections (`sslmode=require`)
- [ ] API keys have appropriate spending limits
- [ ] Testnet is used for all blockchain operations
